# 学生练习与记忆记录

教师在 `/students?class=班级ID` 手动创建和编辑学生；没有自助注册。学生的 `/learn` 只显示本班学习任务与个人练习历史。老师首页的“班级进度”暂不实现。

## 词汇范围

读取 `lessons.active_version` 指向的版本，且该版本 `status=completed`，班级与课程均未删除。每个词按规范化英文拼写去重，同词采用最近结束课程的含义。仅在老师明确点击结课后开放；生成、预览、打印不开放。已结课课程可以生成新版本，旧快照只读，新版本再次结课前该课不贡献词汇。

当前练习的每个词保存来源版本；教师换版或删除课程时，下一次学生请求会检测变化，撤销不再适用的未完成练习。个人记忆和已完成历史不删除。重新加入同词时继续使用已有个人间隔。

## 两阶段状态机

初始状态和词表由 Worker 创建，前端使用共享状态机即时判题和显示动画；每阶段通过后提交该阶段的动作列表。Worker 从已保存状态重放所有动作，重新核算分数。后续题序使用相同状态生成的确定性打乱，保证失败重试后的题目也一致，不接受客户端替换问题或分数。每组默认 10 词（不足时用实际数量），中英文两列独立打乱。完全相同的中文标签不会放入同一组；暂未选中的词保留在待练列表中。

默认使用 v2 日常练习；可以切到 v1 挑战模式。已有 v1 会话保留原规则，不重写已保存题目。新前端显式提交 `mode=practice/challenge`，旧客户端不带模式继续兼容 v1。

- 消消乐：正确配对保留通过记录；错配的两个词分别记错并移除当前卡片。答错后显示正确单词、词义、已有词图、例句及朗读按钮，学生点“看清了，继续”才恢复。当前轮做完后只补练尚未通过的词。
- 中英对决：每词分别验证英文/中文方向。错答涉及的两个词分别记错并清除本阶段这两个词的方向通过记录。确认纠错后先做剩余题，轮末只补缺失方向；干扰项仍来自整组。不会退回阶段 1。
- 挑战模式保留整阶段重来的规则。所有模式都取消自动倒计时重试；日常练习的纠错也随本地动作保存，刷新不会跳过。
- 两阶段全部通过才完成一组，纠正之前的错误仍参与复习安排。阶段内配对、判断、纠错确认和补练都即时在前端执行。正常一组仅有两次答题保存请求，主动离开/超长批次是例外。

未同步动作按学生 ID 放在浏览器 localStorage，不包含密码、姓名或手机号；同浏览器刷新后从服务端状态重放动作继续。主动返回/退出时保存未完成部分，极长练习每 1000 个动作也会保存一次，以控制请求大小。跨设备从最后同步的位置继续；浏览器不允许本地存储时明确提示刷新会回到最后同步处，不改回逐题网络请求。

批量请求 `POST /api/student/sessions/:id/actions` 携带 `{revision, request_id, actions}`。D1 原子批处理同时保存游戏状态与整批事件；完成时一并更新所有词的记忆状态。重放途中任何错误都拒绝整批。网络失败时保留原请求，可刷新恢复、原样重试；相同请求不会重复累计，复用 ID 改变内容会拒绝。服务端版本已更新则以新版本为准，不能覆盖其他设备的进度。同一学生至多一个进行中会话，旧页面的单个 `action` 仍兼容。学生身份由签名 Cookie 与数据库当前账号版本共同核验，API 不接受客户端传入的“已经通过”标记。

## 调度

实现集中在 `lib/student-game.ts` 的 `REVIEW_MINUTES` / `scheduleReview`，无需在 UI 里复制算法。

| 情况 | 下次安排 |
|---|---|
| 首次两阶段通过，期间未错 | 10 分钟后 |
| 到期复习全对 | 依次进入 1、3、7、14、30、60 天 |
| 本组期间出错，即使重试后通过 | 降低一级，5 分钟后复习 |
| 尚未到期主动加练且全对 | 记一组历史，保持原定时间与级别 |

选词先取到期词，再加入未练词，最后才允许提前加练。到期词综合相对逾期时长（逾期时长 / 该词间隔）、间隔级别和历史错词次数排序，优先更弱、更需复习的词；相同优先级随机打散。没有到期/新词时显示下次时间，可以主动“再练一组”。界面不显示伪精确的“记忆百分比”。个人历史使用自己的 `student_id` 保存；一个学生的错误不会改变另一个人的任务。

这是受遗忘和间隔练习研究启发的产品规则，不是声称人人具有相同参数的艾宾浩斯公式。经典遗忘曲线研究和复现使用特定材料与时间点；最合适的间隔还与目标保持时间有关。参考 [Murre & Dros (2015)](https://doi.org/10.1371/journal.pone.0120644)、[Cepeda 等 (2006)](https://pubmed.ncbi.nlm.nih.gov/16719566/)。后续可以根据真实个人记录调整这些参数。

## 进度、个人历史与积分

学生页面顶部把记熟进度和积分放在一起，同时显示初识、巩固中和到期数量。点击进入“单词进度 / 练习历史 / 积分明细”。逐词页面显示真实复习次数、累计错误、下次时间和七档间隔轨迹，不模拟虚假的精确遗忘百分比。统计范围为当前可学词库；已移出课堂的单词在个人记录中仍可回溯，不参与出题。历史明细支持向前翻页。

`student_review_history` 从本版起保存每次完整组练习中各词的错误数、前后级别、下次时间；旧版累计记忆与整组记录保留，不猜测或补造旧版逐词事件。

- 记熟标准：`step >= 3`，即达到 7 天及以上间隔。单次练习全对只算初识，需要到期后多次无错复习才达到记熟；提前反复刷同组不升级。
- 默认每词首次记熟 **10 分**，教师可按班级设置 0–1000。规则变化只影响以后的首次记熟，不回算以前的积分。0 分时也记录首次记熟，之后调价不追补。旧版已经达到记熟的词，下次无错复习时记录一次奖励，不在部署时改写记忆或批量补造记录。
- 以学生 ID＋规范化词为单位只奖励一次，课程更换、单词重复出现、遗忘后重新记熟都不再次奖励；遗忘也不自动扣积分。教师可通过“奖励加分”补发鼓励积分。
- 学生管理表格中的积分按钮打开明细和操作表单，支持奖励加分、兑换抵扣、设置余额，必须填原因并确认调整前后余额。积分不足不能抵扣；不存在学生自行加分/兑换的接口。
- 记忆、逐词历史、首次记熟积分与游戏完成在同一 D1 batch 事务提交。`student_points` 的插入触发余额原子更新，余额有 `CHECK(balance >= 0)`；请求 ID 和奖励唯一索引防止重复发放/抵扣，余额版本防止并发覆盖。失去响应时重试同一笔请求，不另建兑换。

接口：学生自己的 `GET /api/student/history`、`/memory?word=…`、`/points`；教师 `PATCH /api/classes/:id/reward-settings`，`GET/POST /api/students/:id/points`。历史翻页使用 `before` 游标；学生不能通过参数指定他人的身份。设置与积分查询不返回密码。

## 语音、动画和数据

英文显示时自动播放已有 Edge/Sonia 录音，统一经 `/api/audio` 和 R2 缓存。学生只可请求本班已结课词/例句的语音。播放器复用经“开始一组”手势开启的音频元素；翻页、返回或下一次选词会取消旧队列和请求，下载迟到也不会播旧词。若浏览器阻止自动播放，显示“朗读”按钮提示，答题仍能继续。

成功/失败提示是 `lib/student-audio.ts` 中原创 Web Audio 短音，无第三方下载、授权或追踪依赖。卡片消失、抖动、翻页和完成撒花由 CSS 实现，遵守 `prefers-reduced-motion`，不阻塞操作保存。

`students`、`student_sessions`、`student_events`、`student_memory`、`student_review_history`、`student_points`、`student_wallets`、`reward_settings` 是课堂私人数据，只进 D1 和私密备份，浏览器仅暂存当前未同步答题；Git 只保存迁移、代码、教材和公共素材。账号默认格式 `YYYYMMDDNNN`，日期按 Asia/Shanghai，序号在全站该日期的最大编号上递增，至少三位，超过 999 后自然扩为四位。最大编号包含已移除账号；新一天从 001 开始。前端表格提供建议，保存时服务端重新分配并通过唯一约束/事务冲突重试处理并发。手动填写账号仍可用，旧账号不自动改名。初始密码为最终账号后六位，自定义密码保持原值。密码用 PBKDF2-SHA256、随机盐与 100000 次迭代保存。教师更改账号/密码、移除学生后会撤销旧会话。姓名/手机编辑不重置记忆。

验证：`npm run test:students` 测状态机、批量重放、本机恢复、账号日期/序号、双词判错、间隔与音频取消；`npm run test:cloudflare` 在独立临时 D1/R2 中执行真实 HTTP 流程，核对两阶段只有两条保存事件、整批拒绝、丢失回包后的幂等重试、并发账号分配、权限边界、删除和课程换版。

新增验收覆盖纠错停留与定向补练、两个阶段保存、个人历史隔离、记熟积分防刷、老师积分设置、兑换幂等、并发超扣防护与删除后记录保留。
